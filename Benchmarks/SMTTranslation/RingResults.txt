Issue #123: existing Ring model, preprocessing stages

Veil eb41b59673a179ad05773ceca18667ba25b7f079, Lean v4.32.0.
Measured 2026-10-19 after a fresh successful lake build Veil (1085 jobs).
Timings are milliseconds, single observations with concurrent investigation
jobs, intended as scaling evidence rather than stable CI budgets.

Reproduce from repository root:
  python3 Benchmarks/SMTTranslation/ring_stages.py

current = existing veil_bmc order.
early = add veil_intros before the existing order.
local = introduce binders, assume and split the trace conjunction, then
        simplify hypotheses individually (retain all disjunctions).

No SMT solver or proof reconstruction is run in these stage probes. They
finish with sorry; measured times exclude model generation and startup.
maxHeartbeats=0 and maxRecDepth=10000 isolate simp's default maxSteps=100000.
The target_nodes field counts target expression objects only, excluding
hypotheses and proof terms. Local mode's target is False (one node); this
does NOT mean its constraints have disappeared.

All early/local runs below complete. Current depth16/32 fail in nextSimp,
before existential hoisting or SMT. A separate true-HO benchmark isolates
existential hoisting; see QuantifierHoisting.lean and its results file.

The generic conjunction splitter is itself not linear: an additional local
Ring64 experiment took about 5.1 s in split_conj. A production implementation
should avoid repeatedly reconstructing the growing local context.
