The Ivy Formulation

  (∀ R1 R2 V1 V2 Q, ¬ tot.le R2 R1 ∧ proposal R2 V2 ∧ V1 ≠ V2 →
    (∃ N R3 RMAX V, member N Q ∧ ¬ tot.le R3 R1 ∧ one_b_max_vote N R3 RMAX V ∧ ¬ vote N R1 V1))

Reading: If R2 > R1, and V2 is proposed at R2, and V1 ≠ V2, then for any quorum Q, there exists some node N in Q such that: - N sent a 1b for some round R3 ≥ R1 (moved past R1) - N did not vote for V1 in R1

The TLA+ Formulation

SafeAt(v, b) == 
  \A c \in 0..(b-1) :
    \E Q \in Quorums : 
      \A a \in Q : VotedForIn(a, v, c) \/ WontVoteIn(a, c)

-- Used in MsgInv:
(m.type = "2a") => SafeAt(m.val, m.bal) ∧ ...

Reading: Value v is safe at ballot b if for all ballots c < b, there exists a quorum Q where every acceptor either: - Voted for v in ballot c, OR
- Won't vote in ballot c (has moved on: maxBal > c)

Key Structural Differences

Aspect Ivy choosable_proposal TLA+ SafeAt
Quantifier pattern ∀Q ∃N (blocker exists in every quorum) ∃Q ∀a (protecting quorum exists)
Perspective "Blocking" — why V1 can't be chosen "Enabling" — why v can be safely proposed
Trigger When a different value is proposed higher Property of the proposed value itself
Direct vs derived Stated as explicit invariant Derived from message invariants

Logical Equivalence (Intuition)

They're capturing the same safety property from opposite directions:

Ivy says: "Once V2 is proposed at R2, any different value V1 is blocked at all lower rounds R1, because in every quorum there's someone who has moved past R1 and won't vote for V1."

TLA+ says: "Before proposing v at ballot b, we verify that v is 'safe' — for each lower ballot c, there's a quorum that either already voted for v or has moved on."

Why the Different Approaches?

  1. Ivy's approach is more "operational" — it directly tracks the blocking condition that prevents conflicting values. This is the EPR (Effectively Propositional) style where you want explicit, decidable invariants.

  2. TLA+'s approach is more "declarative" — it defines an abstract safety predicate and proves it's maintained. The SafeAt predicate encapsulates the quorum intersection argument.

The Quorum Intersection

Both ultimately rely on quorum intersection. Given two quorums Q1, Q2, they must overlap:

  • Ivy: If V1 could be chosen at R1 (needs all of some Q1 to vote), but every quorum has a blocker, then the blocker in Q1 prevents V1 from being chosen
  • TLA+: If v is safe at b (protected by some Q2), and any value chosen at c needs all of Q1, the overlap ensures consistency

The Ivy version makes the blocker explicit; the TLA+ version hides it inside the WontVoteIn predicate and the quorum existence quantifier.
